# 工作区规则 (Workspace Rules)

- 代码编写原则: 
  - 符合第一性原理、KISS、YAGNI、高内聚低耦合原则、SOLID 原则、DRY；
  - Error能处理完善
  - 保持项目一致性
  - 确保性能与复杂度平衡
  - 具备专业的设计模式，符合业内最佳实践
  - 要有框架思维: 当用户有增删改/重构代码的需求, 要先思考它对项目架构的影响, 再带着整体框架来解决问题
- 与用户交互的原则:
  - 所有回复内容的非代码部分, 必须中文优先 (包括各种artifacts)
  - 永远是回复优先，而非行动优先;
  - 简化交互, 节省token: 
    - 任务简单时: 不准编排`实施方案, task list, walkthrough, test`;
    - 当出于debug的需要时: 你可以直自己创建/删除辅助代码文件, 而无需征得我的统一!
  - 善用web search
- 命令执行原则:
  - 执行前确认项目虚拟环境, 如uv
  - 风险预评估: 所有命令都尽量自主执行, 仅当你评估其风险性过大时, 才交由我审查执行
