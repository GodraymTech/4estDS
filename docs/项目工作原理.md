# 项目工作原理

本文按当前代码说明 4estDS 如何从输入影像生成单木数据、报告、GIS 图层和前端地图。

## 1. 一次推理的数据流

```text
输入影像
  |
  v
preprocess.prepare_inference_image
  - 读尺寸
  - 判断 TIFF/COG/tiled 状态
  - 必要时转 COG
  - SCOPE 自标定 tile_size/overlap_rate
  - 路由到 direct / on_the_fly / physical_slice
  |
  v
engine.run_inference
  - 生成窗口清单
  - ImageSource 读窗
  - BaseDetector 批量预测
  - tile 内坐标回写到全图坐标
  - WBF 融合去重
  |
  v
tasks.run_infer_pipeline
  - 计算地块空间信息
  - 确定 acquisition_time/location
  - 写 tree_observations
  - 可选 CHM/DSM/DEM/LAS 融合
  - 可选绘制检测框
  - 自动报告
  - 可选 GIS 导出
  |
  v
service.run_inference_job
  - start_run_log
  - run_infer_pipeline
  - finish_run_log
  - 可选 promote_run
```

## 2. 分层边界

### Interface

- `src/forestds/cli.py`: Typer CLI，只解析参数、设置日志、构造请求。
- `src/forestds/api/main.py`: FastAPI app factory。
- `src/forestds/api/routers/*`: HTTP 边界，负责校验、序列化、错误映射。
- `web/src/*`: 前端一张图、任务中心、台账、报告等页面。

### Application Service

- `src/forestds/service.py`: 推理作业生命周期唯一入口。
- `src/forestds/contracts.py`: CLI/API/Worker 之间共享的 DTO。
- `src/forestds/worker/actors.py`: Dramatiq actor，负责异步队列和模型常驻缓存。

### Use Case

- `src/forestds/tasks/infer.py`: 单图推理完整业务编排。
- `src/forestds/tasks/batch.py`: 多图/目录批量推理。
- `src/forestds/tasks/train.py`: 训练入口。
- `src/forestds/tasks/preprocess_train.py`: 训练数据规整。

### Domain

- `preprocess/`: COG、SCOPE、自适应切片、静态切片。
- `engine/`: `ImageSource` 适配器、窗口推理、坐标回写。
- `detect/`: `BaseDetector`、`mock`、`ultralytics` 适配器。
- `postprocess/`: WBF 融合去重。
- `fusion/`: CHM、DSM/DEM、LAS 采样与树高/体积特征。
- `lifecycle/`: 跨时相单木匹配。
- `report/`: 指标计算与报告渲染。
- `export/`: GIS 图层导出。

### Infra

- `db/schema.py`: SQLite DDL。
- `db/writer.py`: run、地块、观测、发布、生命周期写入。
- `db/reader.py`: 地块、run、观测、缓存读取。
- `api/storage.py`: 上传文件存储抽象。
- `paths.py`: `~/.4estDS` 运行期目录。

## 3. CLI、API、Worker 如何复用同一条业务路径

CLI 单图推理:

```text
cli.cmd_infer
  -> InferenceRequest
  -> service.run_inference_job(..., publish=False)
  -> tasks.run_infer_pipeline
```

API/Worker 异步推理:

```text
POST /api/v1/jobs/infer
  -> InferenceRequest / BatchInferenceRequest
  -> enqueue_inference / enqueue_batch_inference
  -> worker.actors.infer_actor / batch_actor
  -> service.run_inference_job(..., publish=True)
```

这保证了命令行、前端任务中心、后续 SDK 不会各自复制一套 run 生命周期。

## 4. 预处理路由

当前 `prepare_inference_image` 有三种模式:

| 模式 | 触发条件 | 特点 |
| --- | --- | --- |
| `direct` | 小图，不超过 seed window 阈值 | 整图进入内存源推理 |
| `on_the_fly` | 大图 + tiled TIFF/COG + dynamic | 动态窗口读，不落盘切片 |
| `physical_slice` | static 或不支持随机读 | 先切片落盘，再从目录读瓦片 |

普通非分块 TIFF 在 dynamic 模式下会尝试转换为同目录 `_cog.tif`。如果转换失败，会降级到静态切片。

## 5. SCOPE 自标定

SCOPE 的职责是给大图自动选择 `tile_size` 和 `overlap_rate`。当前代码中的触发条件:

- 推理模式是 `physical_slice` 或 `on_the_fly`。
- 输入是 TIFF。
- `preprocess.scope.enable=true`。
- 用户没有显式传入 `--tile-size`。

如果用户显式指定 `--tile-size`，系统直接使用用户参数，避免自动寻优覆盖人工控制。

## 6. 推理内核

`engine.run_inference` 只关心两个抽象:

- `ImageSource`: 提供 `width`、`height`、`read_window` 或已落盘瓦片清单。
- `BaseDetector`: 提供 `predict_batch`。

流程:

1. 根据图像尺寸和 `InferenceConfig` 生成切片窗口。
2. 分批读取窗口并推理。
3. 将检测框从窗口坐标平移到全图坐标。
4. 对触及内部切片边界的框打 `truncated` 标记，并在 WBF 权重中降权。
5. 用 WBF 按标签、IoU、中心距离门控融合。

## 7. 数据库三层模型

```text
tree_observations
  原始观测层: 每个 run 的最终融合结果，保留 run_id，可重复

tract_trees
  地块规范单木层: 某地块当前 active run 的正式版本

tree_individuals
  跨时相个体层: 多个 acquisition_time 之间的同株关联
```

CLI 推理默认只写 `tree_observations` 和 `run_logs`。需要成为正式版本时执行:

```bash
uv run 4estds db promote --run-id <run_id>
```

API/Worker 异步推理默认 `publish=True`，成功后会尝试自动发布。

## 8. 前端如何取数

前端 API 集中在 `web/src/shared/api/endpoints.ts`:

- 地块列表: `GET /tracts`
- 地块统计: `GET /tracts/summaries`、`GET /tracts/{id}/summary`
- 观测图层: `GET /tracts/{id}/observations?geometry=point|crown`
- 任务历史: `GET /jobs`
- 作业状态: `GET /jobs/{job_id}`
- 作业日志: `GET /jobs/{job_id}/logs`
- 报告下载: `GET /tracts/{id}/report`
- 图层导出: `GET /tracts/{id}/export`

开发时 Vite 把 `/api` 代理到 FastAPI；生产应由 nginx 或网关统一反代。

## 9. 常见设计取舍

### 为什么 API 不直接跑推理

推理可能长时间占用 GPU。API 只提交作业，Worker 串行消费 GPU 队列，避免 HTTP 进程被大任务阻塞。

### 为什么 Worker 默认单并发

当前 worker 会在进程内缓存检测器权重。GPU 任务单并发能减少显存竞争，并降低多任务同时读写 run 日志和大图资源的复杂度。

### 为什么观测和正式版本分开

同一地块可能有多次推理、不同模型、不同参数。`tree_observations` 保留全部可追溯结果，`tracts.active_run_id` 指定哪个 run 是当前正式版本。

### 为什么内置瓦片服务只作为轻量方案

`api/routers/tiles.py` 可以把本地 GeoTIFF 实时渲染成 XYZ PNG，但它不是生产级 TiTiler 替代品。生产环境应优先接入专用瓦片服务或预切片服务。
