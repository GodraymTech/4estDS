# 有效区域与智能复核使用说明

本文说明地块有效区域和单 TIFF 智能复核的实际操作、恢复方式与故障处理。正式结果始终以每张 TIFF 的 `active run` 为准；AI attempt 只是草稿内尝试，发布前不会改变地图、统计、报告或导出。

## 一、入口与结果语义

- 地图地块卡、台账操作列可进入“编辑有效区域”；任务中心显示有效面积并提供返回地图的入口。
- 一级导航“智能复核”进入 `/review`，首页可继续最近草稿，或按时相和 TIFF 新建会话。
- “基于已有结果”读取该 TIFF 当前 active run；“从 0 开始”建立空工作集。
- 一张 TIFF 可以有多次 infer/review 运行，但仅发布动作切换该 TIFF 的 active run；其他 TIFF、父 run 和父观测不受影响。

## 二、划定有效区域

1. 在地图选择地块并打开“编辑有效区域”。
2. 可绘制、增删顶点、挖洞、分割、合并，或导入 GeoJSON、Shapefile、GPKG、KML、FGB。
3. 导入多图层文件时先选择图层；预检会显示 CRS、面数量、面积、越界和裁剪提示。
4. 保存时后端重新验证几何并精算公顷面积。若他人已修改地块，接口返回 `409`，重新加载后再编辑。

有效区域必须为合法 Polygon/MultiPolygon 且位于地块边界内。空值等同完整地块边界。Shapefile 上传必须同时包含 `.shp/.shx/.dbf`，缺少组成文件或 CRS 无法识别时应重新选择完整文件组；不要手工猜测 CRS。

有效区域会在推理前跳过完全位于外部的窗口，只给边界窗口建立局部 mask；结果按检测框中心点过滤。系统不会创建 TIFF 全分辨率 mask。

## 三、智能复核工作台

### 草稿和人工编辑

- 工作台按对象支持新建、删框、改框、改类、备注、接受/拒绝和批量状态操作。
- `Ctrl/⌘+Z` 撤销，`Ctrl/⌘+Y` 重做；输入框聚焦时不会触发工作台快捷键。
- 每次写入携带 revision。出现 `409` 表示另一窗口已更新草稿，重新加载可避免覆盖他人修改。
- 草稿以原子文件恢复；浏览器关闭或服务重启后，从 `/review` 的最近草稿继续。

### 文本与视觉 Prompt

- 文本 Prompt 的类别标识、中文显示名和模型描述分开保存；可为同一树种填写更适合模型的描述。
- 视觉 Prompt 选择当前 TIFF 中已确认的参考框。参考图局部窗口和 exemplar box 只用于编码提示，不会投影到目标窗口。
- “当前视口”适合快速试验，“整图”用于最终扩散。整图 attempt 使用低优先级队列，不阻塞短视口任务。
- 成功后选择“追加候选”或“替换范围内未确认 AI”；人工确认对象和父结果不会被替换。
- “扩散到全图”复用原 attempt 的 prompt、阈值和合并方式。取消只终止该 attempt，不删除草稿。

模型文件缺失时，能力区会明确显示不可用，请检查 `review.models` 与 `mobileclip_weights`。CUDA OOM 时系统只把当前 batch 减半重试一次；仍失败时保留错误摘要，缩小视口或降低 `review.batch_size` 后重试。

### 实例 Mask

YOLOE-Seg 候选可显示实例 mask。工作台左下可开关 mask 和调整透明度；选中带 mask 的对象后可用增加/擦除画笔编辑。弹窗内撤销重做只影响本次画笔，取消不会写草稿；确认后同步外接框、像素轮廓、`crown_geom/geom_crown`，仍可使用工作台全局撤销。

### 发布

发布前必须解决跨类别冲突、有效区域外对象和无类别对象。确认后系统在一个事务内创建 review run、写入最终全量 observations、切换目标 TIFF active run 并结束 session；任一步失败都会整体回滚，草稿仍可继续。

## 四、配置边界

配置优先级为 `configs/default.yaml`、用户配置、`forestds_SECTION__KEY` 环境变量、CLI。后端 `/api/v1/reviews/capabilities` 返回前端需要的默认范围、合并方式、阈值和限制，页面不复制这些默认值。

| 配置 | 单位与合法值 | 性能影响 | 生效方式 |
| --- | --- | --- | --- |
| `effective_area.area_refresh_ms` | 毫秒，建议 `>=16` | 越小拖动刷新越频繁 | 前端重载 |
| `effective_area.simplify_tolerance_px` | 屏幕像素，`>=0` | 仅显示建议，不改保存几何 | 前端重载 |
| `effective_area.boundary_epsilon_m` | 米，`>=0` | 越大边界判断越宽松 | 重启 API |
| `effective_area.mask_cache_size` | 项数，`>=1` | 越大重复转换更少、内存更高 | 重启 Worker |
| `review.model_variant` | `26x/26l` | 26x 精度和显存开销通常更高 | 重启 Worker |
| `review.device` | `null/cpu/cuda:N` | 决定推理设备 | 重启 Worker |
| `review.model_input` | 像素，正整数 | 越大显存和耗时越高 | 重启 Worker |
| `review.conf_threshold` | `0..1` | 越低候选越多 | 新 attempt |
| `review.default_scope` | `viewport/full` | full 默认任务更重 | 页面重新载入 |
| `review.default_merge_mode` | `append/replace_ai_in_scope` | 不影响模型耗时 | 页面重新载入 |
| `review.tile_size` | 像素，`>=128` | 越大单窗显存越高、窗口更少 | 重启 Worker |
| `review.batch_size` | 个，`>=1` | 越大吞吐更高、显存更多 | 重启 Worker |
| `review.viewport_max_windows` | 窗口数，`>=1` | 限制交互任务最长时延 | 重启 Worker |
| `review.max_candidates_per_attempt` | 对象数，`>=1` | 限制草稿内存和响应体 | 重启 Worker |
| `review.bbox_page_size` | 对象数，建议 `>=100` | 控制前端批次大小 | 页面重新载入 |

## 五、性能基线与 MVT 决策

2026-07-18 在当前开发机实测：

- 真实 `Q12.tif` 为 43,841×22,816；按 1024 窗口共 989 个，模拟有效区域时 611 个在读取前跳过、300 个内部、78 个边界。受控读取 16 个有效窗口总耗时 0.954 秒，进程峰值 RSS 169 MB。
- 1,000/5,000/10,000 候选合并与 WBF 分别约 0.02/0.10/0.19 秒。
- 10,000 对象单项编辑约 0.05 秒，撤销历史只保存受影响对象；前端增量 patch 保持其余 9,999 个对象引用不变。
- `/review` 保持路由级懒加载；普通页面首包不包含复核工作台、Terra Draw 或 Turf 编辑器。

当前 10,000 对象基线未证明需要 MVT，因此继续使用 bbox/JSON 与增量状态，不引入 MVT 双写和 ID 映射。若真实业务规模和浏览器性能数据超过该基线，再依据首屏延迟、交互帧率和响应体实测启动 MVT 设计。

## 六、排错速查

- `409 revision_conflict`：另一窗口已保存，重新加载草稿。
- `active_run_changed`：复核期间正式结果已变化，基于新 active run 新建会话。
- `outside_effective_area`：移动、拒绝或删除有效区域外对象。
- `review_queue_unavailable`：检查 Redis、Worker 和 `review_gpu` 队列。
- `tiff_file_missing`：台账中的 TIFF 路径当前不可访问。
- `viewport_window_limit`：缩小当前视口，或在确认资源后调整配置。
- 模型缺失/OOM：检查能力接口和本地模型路径；降低 batch/视口范围后重试，不要触发在线下载。
