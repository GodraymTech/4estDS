# 智能复核模块重构方案

基于 TrexLabel 工作台设计范式，对 `/review` 及其子路由进行全面重构。核心目标：将 TrexLabel 的标注工作台 UX 嫁接到单张大 TIFF 的 GIS 复核环境，同时保留项目已有的窗口化推理、草稿持久化、revision CAS 等 GIS 级能力。

> [!IMPORTANT]
> **命名确认**：模式从 `based_on_active / from_scratch` 更名为 `inherit / fresh`，前端显示为 `继承 / 新启`。后端字段值需同步修改还是仅前端映射？推荐后端也改，避免认知分裂。[我评论: 按你推荐的来]

> [!WARNING]
> **工作台重构范围**：当前 ReviewWorkbench 是一个 420 行的单文件巨组件 + 3 个子面板。重构将拆分为 ~10 个专职组件。这是破坏性重构，旧 ReviewWorkbench.tsx 将被完全替换。

> [!IMPORTANT]
> **地图引擎选择**：当前工作台用 `<img>` 展示 TIFF 降采样预览，不支持平移缩放。重构后中央画布需要真正的地图引擎（项目已有 MapWorkspacePage 使用 map-core）。是复用项目现有的 map-core 模块，还是在工作台内用轻量方案（如直接用 canvas + pointer events 实现平移缩放）？
> - **方案 A**：复用 `shared/map-core`（一致性好，但耦合重）
> - **方案 B**：工作台内自建轻量 canvas viewer（独立性强，适合单 TIFF 场景）
> - 我倾向 **方案 B**，因为复核工作台是单 TIFF 全屏编辑器，不需要地图底图切换、多图层叠加等 map-core 能力 [我评论: 按你推荐的来]

### 组件 2：后端连接状态模块

#### [NEW] [ConnectionStatus.tsx](file:///home/ray/rays/repos/4estDS/web/src/shared/ui/ConnectionStatus.tsx)

**设计思路** — 参考 VSCode/JetBrains 的服务连接指示器：

- **位置**：HeaderBar 的帮助按钮和亮色切换按钮之间
- **核心交互**：
  - 图标按钮，类似其他 HeaderBar 按钮的风格（`type="text"`，同色系）
  - 三种状态视觉：
    - ✅ 已连接（绿色圆点 badge）：`ApiOutlined` 图标
    - ⚠️ 降级（橙色圆点）：存储或数据库部分不可用
    - ❌ 断开（红色圆点 + 呼吸动画）：后端不可达
  - 点击展开 Popover 面板，显示：
    - 服务名称 + 版本号（来自 `/healthz`）
    - 各依赖检查项状态（来自 `/health`）：storage ✅ / database ✅
    - 响应延迟（ms）
    - 上次成功探测时间
    - 手动"立即检测"按钮
    - API 地址显示（env.apiBase）

- **自动探测策略**：
  - 使用 TanStack Query 定时轮询 `/healthz`（轻量 liveness），间隔 30s
  - 状态变化时（ok→fail 或 fail→ok）自动触发一次 `/health`（重量 readiness）获取详细诊断
  - 连续 2 次 `/healthz` 失败才切换到"断开"状态（避免单次网络抖动误报）
  - 断开状态下轮询间隔缩短到 5s

### 组件 3：ReviewWorkbench 工作台重构（重中之重）

这是核心重构。参考 TrexLabel 的专业标注编辑器布局，结合项目的单 TIFF GIS 场景。

#### 整体布局架构（参照 TrexLabel）

```
┌─────────────────────────────────────────────────────────────────┐
│ TopBar: 会话信息 │ 撤销/重做 │ 连接状态 │ 返回/发布         │
├────┬────────────────────────────────────────────────────┬───────┤
│    │                                                    │       │
│ T  │                                                    │ 右    │
│ o  │                                                    │ 侧    │
│ o  │              中央画布 (Canvas Viewer)               │ 面    │
│ l  │         TIFF 降采样预览 + 检测框 + Mask 叠加        │ 板    │
│ b  │              支持平移 / 缩放 / 框选                 │       │
│ a  │                                                    │       │
```

**与 TrexLabel 的关键映射关系**：

| TrexLabel 元素 | 4estDS 复核工作台对应 | 差异说明 |
|---|---|---|
| 左侧垂直工具栏（光标/框选/多边形/智能标框/分割） | **ToolRail**：光标选择 / 手动画框 / AI 智能标框(text prompt) / AI 视觉样例(visual prompt) | 无多边形工具（树冠是 mask 不是多边形）；AI 工具直接整合到工具栏 |
| 顶栏图片导航 `< 1/4 >` | 不需要 — 单 TIFF 场景无多图切换 | 替代为会话信息 + revision tag |
| 右侧"图片信息"面板 | **TiffInfo 折叠面板**：文件名、尺寸、CRS、GSD | 附加 GIS 元数据 |
| 右侧"标注"列表 | **对象列表面板**：按类别分组，显示 status tag，支持多选批量操作 | 增加 conflict 标识 |
| 底部图片缩略图条 | **对象缩略图条**：当前过滤后的检测框裁剪缩略图，横向滚动 | 裁剪自 TIFF 预览图的局部区域 |
| 类别创建（搜索框 + 输入创建） | **类别管理面板**：搜索已有类别 + 输入创建新类别，每个类别色块可点选切换当前活跃类别 | 对应现有 category_catalog |
| "标注统计"按钮 | **统计摘要**：集成在右侧面板顶部，显示总数/接受/拒绝/冲突 | 实时更新 |
| "导出标注"按钮 | **发布按钮**：原子发布为 review run | 语义不同但位置对应 |

#### 3.2 CanvasViewer — 中央画布

**当前问题**：用 `<img>` + CSS 百分比定位 `<button>` 实现检测框叠加，不支持平移缩放。

**重构方案**：
- 基于 Canvas 2D 或 SVG viewBox 实现轻量级平移缩放 viewer
- **图层叠加**（由下至上）：
  1. TIFF 降采样预览图（来自 `/reviews/{id}/preview`）
  2. Mask SVG 图层（现有 `MaskOverlayLayer` 逻辑保留）
  3. 检测框图层（矩形 + 类别标签 + 状态色）
  4. 交互层（选中框高亮、拖拽手柄、新建框绘制）
- **交互能力**：
  - 鼠标滚轮缩放（以光标为中心）
  - 中键/Space+左键拖拽平移
  - 左键点击选中检测框
  - Ctrl/Cmd+左键多选
  - 选中框显示 8 方向调整手柄（拖拽调整 box_px）
  - 双击检测框进入属性编辑（右侧 Inspector 聚焦）
- **视觉风格**：[我评论: 支持跟随全局亮暗切换]
  - 深色背景（`#07110f`，保持现有暗色主题）
  - 画布外围区域有细微径向渐变
  - 检测框颜色按类别着色（复用 `categoryColor`）
  - 选中框：白色光晕 + 加粗边框
  - pending 状态框：虚线边框
