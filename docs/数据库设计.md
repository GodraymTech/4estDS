# 数据库设计

本文是 4estDS 新一代数据库模型设计稿，用于取代旧版「数据表设计与工作机制」中的表结构说明。设计目标是围绕真实业务层级建模：

```text
地块 tract
  -> 地块时相 tract_phase
    -> TIFF 影像 tiff
      -> 单木观测 tree_observation

跨时相单木个体 tree_individual
  -> 多个时相状态 tree_phase_state
  -> 多条单木观测 tree_observation
```

本设计不保留旧库历史包袱；未来代码、API、前端和迁移脚本都应围绕本模型重构。

## 1. 关键判断

### tracts 和 tract_phases 不合并

`tracts` 是稳定业务对象，表达“这块地叫什么、属于哪个行政区、默认边界是什么”。`tract_phases` 是时间切片，表达“这块地在某一天有哪些 TIFF、覆盖状态如何、当前发布 run 是哪次”。

如果合并，多个时相会重复存储同一地块的行政区、名称、默认边界等稳定信息；如果不重复，又无法优雅表达一个地块的多个时相。因此二者分离是更稳健的范式。

### 术语层级

项目的主层级应是：

```text
地块 -> 时相 -> TIFF -> 单木观测
```

其中“单木个体”不是 TIFF 的下级。它代表跨时相追踪后的真实树木身份，和多个时相、多次观测关联。

### footprint_bbox 不是检测框列表

旧名 `bounds_bbox` 容易被误解为“所有推理检测框列表”。新模型中改为 `footprint_bbox`，只表示 TIFF 覆盖范围的外接矩形：

```json
[min_lng, min_lat, max_lng, max_lat]
```

所有推理所得检测框只存放在 `tree_observations.box_px`、`tree_observations.box_geo`，绝不塞进 TIFF 表。

### tree_individuals 不直接使用 new 状态

`new` 不是一个长期身份状态，而是“某棵树相对某个时相第一次出现”的时相状态。比如一棵树在 20260707 是 `new`，到 20260807 就应变成 `reobserved` 或 `alive`。

因此：

- `tree_individuals.global_status` 保存长期状态：`alive / missing / removed / unknown`
- `tree_phase_states.lifecycle_status` 保存时相状态：`new / reobserved / missing / removed / unknown`

这样不会让 `new` 这种瞬时语义污染全局个体表。

### 面积估算

树冠面积拆为估计值和真实值：

- `crown_area_geo_est`: 估计面积，当前默认由树冠地理宽高相乘得到。
- `crown_area_geo_real`: 真实面积，未来实例分割或精细冠幅多边形可直接计算。

应在配置中新增面积算法参数，语义类似体积计算的 `volume_method`：

```text
area_method = bbox_product | polygon_area | mask_area
```

当前阶段默认使用 `bbox_product`，实例分割属于后续 TODO。

## 2. 表设计

### 2.1 tracts: 地块表

表示一个稳定存在的业务地块。`tract_id` 本身就是地块名称，不再单独设置 `name` 列。

| 列 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `tract_pk` | text | 是 | 内部主键。建议使用安全编码后的 `{region_id}_{tract_id}`，避免业务名特殊字符影响外键 |
| `region_id` | text | 是 | 行政区划 ID，格式为 `市_县`，如 `湛江_徐闻` |
| `tract_id` | text | 是 | 用户可见地块 ID，也是地块名称；同一 `region_id` 内唯一 |
| `boundary_geom` | text/json | 否 | 地块默认多边形，SQLite 阶段存 GeoJSON 或 WKT 文本，PostGIS 阶段迁移为 Geometry |
| `boundary_source` | text | 是 | 边界来源：`manual / auto_from_single_tiff / unset` |
| `coverage_status` | text | 是 | 地块总体影像覆盖状态：`none / partial / full`, 默认none, 后两者由用户手动指定 |
| `notes` | text | 否 | 备注 |
| `created_at` | text | 是 | 创建时间，ISO 8601 |
| `updated_at` | text | 是 | 更新时间，ISO 8601 |

约束：

- `PRIMARY KEY (tract_pk)`
- `UNIQUE (region_id, tract_id)`
- `CHECK (boundary_source IN ('manual', 'auto_from_single_tiff', 'unset'))`
- `CHECK (coverage_status IN ('none', 'partial', 'full'))`

默认规则：

- 用户手动指定 `tract_id` 时直接使用。
- 用户未指定 `tract_id`，且地块下只有一个正射 TIFF 时，默认使用该 TIFF 文件名 stem。
- 用户手动指定边界时，`boundary_source = 'manual'`。
- 只有一个 TIFF 且未指定边界时，用 TIFF 四角自动生成 `boundary_geom`，`boundary_source = 'auto_from_single_tiff'`。
- 多 TIFF 或无 TIFF 且未指定边界时，`boundary_geom = NULL`，`boundary_source = 'unset'`。

### 2.2 tract_phases: 地块时相表

表示某个地块在某一天的业务状态。不单独建 `phases` 维表，`phase_id` 直接作为强语义日期字段。

| 列 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `tract_phase_pk` | text | 是 | 主键。建议使用安全编码后的 `{tract_pk}_{phase_id}` |
| `tract_pk` | text | 是 | 所属地块 |
| `region_id` | text | 是 | 冗余查询字段，来自 `tracts.region_id` |
| `tract_id` | text | 是 | 冗余查询字段，来自 `tracts.tract_id` |
| `phase_id` | text | 是 | 时相 ID，固定格式 `YYYYMMDD` |
| `boundary_geom` | text/json | 否 | 该时相下的边界修正；为空时继承 `tracts.boundary_geom` |
| `coverage_status` | text | 是 | 当前时相影像覆盖状态：`none / partial / full` |
| `active_run_id` | text | 否 | 当前发布的推理 run |
| `created_at` | text | 是 | 创建时间，ISO 8601 |
| `updated_at` | text | 是 | 更新时间，ISO 8601 |

约束：

- `PRIMARY KEY (tract_phase_pk)`
- `UNIQUE (tract_pk, phase_id)`
- `FOREIGN KEY (tract_pk) REFERENCES tracts(tract_pk) ON DELETE CASCADE`
- `CHECK (phase_id GLOB '[0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9]')`
- `CHECK (coverage_status IN ('none', 'partial', 'full'))`

### 2.3 tiffs: TIFF 表

表示某个时相下的一张 TIFF 图像。`tiff_id + phase_id` 唯一标识一个 TIFF 图像。

| 列 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `tiff_id` | text | 是 | 5 位哈希，基于 TIFF 四角坐标生成 |
| `phase_id` | text | 是 | 时相 ID，固定格式 `YYYYMMDD` |
| `tract_phase_pk` | text | 是 | 所属地块时相 |
| `file_name` | text | 否 | 原始文件名，仅作展示和默认地块名来源 |
| `path_versions` | text/json | 是 | 正射影像路径版本：`{读取日期YYYYMMDD: 原始完整路径}` |
| `multisource_path_versions` | text/json | 是 | 多源文件路径版本：`{chm:{YYYYMMDD:path}, dsm:{...}, dem:{...}, las:{...}}` |
| `footprint_geom` | text/json | 是 | TIFF 四角多边形，建议统一为 WGS84 |
| `footprint_bbox` | text/json | 否 | TIFF 覆盖范围外接矩形：`[min_lng, min_lat, max_lng, max_lat]` |
| `corner_hash_input` | text | 是 | 哈希前的规范化四角坐标字符串；统一经纬坐标系和 3 位小数 |
| `crs_epsg` | integer | 否 | 原始 CRS EPSG |
| `crs_wkt` | text | 否 | 原始 CRS WKT |
| `geotransform` | text/json | 否 | 原始仿射变换参数 |
| `pixel_width` | integer | 否 | 像素宽 |
| `pixel_height` | integer | 否 | 像素高 |
| `gsd` | real | 否 | 地面分辨率 |
| `band_count` | integer | 否 | 波段数 |
| `dtype` | text | 否 | 栅格数据类型 |
| `nodata` | real | 否 | NoData 值 |
| `inference_status` | text | 是 | 推理状态：`pending / inferred` |
| `created_at` | text | 是 | 创建时间，ISO 8601 |
| `updated_at` | text | 是 | 更新时间，ISO 8601 |

约束：

- `PRIMARY KEY (tiff_id, phase_id)`
- `FOREIGN KEY (tract_phase_pk) REFERENCES tract_phases(tract_phase_pk) ON DELETE CASCADE`
- `CHECK (length(tiff_id) = 5)`
- `CHECK (phase_id GLOB '[0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9]')`
- `CHECK (inference_status IN ('pending', 'inferred'))`

路径规则：

- 路径必须保持用户传入的原始字符串，不做 `wslpath`、绝对化、大小写转换等处理。
- 读取正射 TIFF 路径时，取 `path_versions` 中日期最大的 key。
- 读取多源文件路径时，先按文件类型进入 `multisource_path_versions`，再取该类型下日期最大的 key。

### 2.4 runs: 运行记录表

记录每一次推理、训练、报告、批处理、导出等任务。

| 列 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `run_id` | text | 是 | 6 位哈希 |
| `parent_run_id` | text | 否 | 父 run，批处理或子任务追踪使用 |
| `tract_phase_pk` | text | 否 | 关联地块时相；训练任务可为空 |
| `tiff_id` | text | 否 | 针对单 TIFF 的任务填写 |
| `phase_id` | text | 否 | 关联 TIFF 时必须填写 |
| `task_type` | text | 是 | 任务类型：`infer / train / report / batch / export / postprocess / import / track` |
| `model_arch` | text | 否 | 模型架构或后端 |
| `status` | text | 是 | 运行状态：`queued / running / succeeded / failed / canceled` |
| `slice_size` | integer | 否 | 切割尺寸；用于推理、批处理、报告复现 |
| `input_json` | text/json | 否 | 输入信息 |
| `params_json` | text/json | 否 | 参数快照，包含 `area_method`、`volume_method` 等 |
| `metrics_json` | text/json | 否 | 指标 |
| `error` | text | 否 | 错误信息 |
| `started_at` | text | 是 | 开始时间，ISO 8601 |
| `ended_at` | text | 否 | 结束时间，ISO 8601 |
| `duration_s` | real | 否 | 耗时秒数 |
| `created_at` | text | 是 | 创建时间，ISO 8601 |

约束：

- `PRIMARY KEY (run_id)`
- `FOREIGN KEY (parent_run_id) REFERENCES runs(run_id) ON DELETE SET NULL`
- `FOREIGN KEY (tract_phase_pk) REFERENCES tract_phases(tract_phase_pk) ON DELETE SET NULL`
- 可选复合外键：`FOREIGN KEY (tiff_id, phase_id) REFERENCES tiffs(tiff_id, phase_id) ON DELETE SET NULL`
- `CHECK (length(run_id) = 6)`
- `CHECK (task_type IN ('infer', 'train', 'report', 'batch', 'export', 'postprocess', 'import', 'track'))`
- `CHECK (status IN ('queued', 'running', 'succeeded', 'failed', 'canceled'))`

### 2.5 tree_individuals: 单木个体表

表示跨时相追踪后的真实单木身份。它不是某个 TIFF 的下级，而是跨时相实体。

| 列 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `individual_id` | text | 是 | 8 位哈希，全球唯一 |
| `first_seen_phase_id` | text | 否 | 首次出现时相 |
| `last_seen_phase_id` | text | 否 | 最近出现时相 |
| `global_status` | text | 是 | 长期状态：`alive / missing / removed / unknown` |
| `tracking_confidence` | real | 否 | 跨时相追踪置信度 |
| `growth_json` | text/json | 否 | 生长轨迹统计 |
| `created_at` | text | 是 | 创建时间，ISO 8601 |
| `updated_at` | text | 是 | 更新时间，ISO 8601 |

约束：

- `PRIMARY KEY (individual_id)`
- `CHECK (length(individual_id) = 8)`
- `CHECK (global_status IN ('alive', 'missing', 'removed', 'unknown'))`

### 2.6 tree_phase_states: 单木时相状态表

表示某棵树在某个地块时相下的生命周期状态。`new` 放在这里，而不是放在全局个体表。

| 列 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `tree_phase_state_id` | text | 是 | 主键，建议使用安全编码后的 `{individual_id}_{tract_phase_pk}` |
| `individual_id` | text | 是 | 单木个体 |
| `tract_phase_pk` | text | 是 | 所属地块时相 |
| `lifecycle_status` | text | 是 | 时相状态：`new / reobserved / missing / removed / unknown` |
| `representative_observation_id` | text | 否 | 该时相下代表观测 |
| `confidence` | real | 否 | 生命周期判定置信度 |
| `created_at` | text | 是 | 创建时间，ISO 8601 |
| `updated_at` | text | 是 | 更新时间，ISO 8601 |

约束：

- `PRIMARY KEY (tree_phase_state_id)`
- `UNIQUE (individual_id, tract_phase_pk)`
- `FOREIGN KEY (individual_id) REFERENCES tree_individuals(individual_id) ON DELETE CASCADE`
- `FOREIGN KEY (tract_phase_pk) REFERENCES tract_phases(tract_phase_pk) ON DELETE CASCADE`
- `CHECK (lifecycle_status IN ('new', 'reobserved', 'missing', 'removed', 'unknown'))`

### 2.7 tree_observations: 单木观测表
### 2.7 tree_observations: 单木观测表

表示某次 run 在某张 TIFF 或某个地块时相中检测到的一棵树。这里保存事实观测和度量值，不保存长期身份判断。

| 列 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `observation_id` | text | 是 | 观测 ID |
| `individual_id` | text | 否 | 匹配到的跨时相单木个体 |
| `run_id` | text | 是 | 来源 run |
| `tract_phase_pk` | text | 是 | 所属地块时相 |
| `tiff_id` | text | 否 | 来源 TIFF |
| `phase_id` | text | 是 | 时相 ID |
| `species` | text | 否 | 类别 |
| `confidence` | real | 否 | 检测置信度 |
| `center_geom` | text/json | 否 | 中心点地理坐标 |
| `crown_geom` | text/json | 否 | 树冠多边形；当前可由检测框近似，未来实例分割替换为真实轮廓 |
| `box_px` | text/json | 否 | 像素检测框 `[x1, y1, x2, y2]` |
| `box_geo` | text/json | 否 | 地理检测框 |
| `crown_width_px` | real | 否 | 树冠像素宽 |
| `crown_height_px` | real | 否 | 树冠像素高 |
| `crown_width_geo` | real | 否 | 树冠地理宽度 |
| `crown_height_geo` | real | 否 | 树冠地理高度 |
| `crown_area_px_est` | real | 否 | 像素面积估计值，默认 `crown_width_px * crown_height_px` |
| `crown_area_px_real` | real | 否 | 像素真实面积，未来由实例分割 mask 或精确多边形得到 |
| `crown_area_geo_est` | real | 否 | 地理面积估计值，默认 `crown_width_geo * crown_height_geo` |
| `crown_area_geo_real` | real | 否 | 地理真实面积，未来由实例分割 mask 或精确多边形得到 |
| `area_method` | text | 否 | 面积算法：`bbox_product / polygon_area / mask_area` |
| `height` | real | 否 | 树高 |
| `height_source` | text | 否 | 高度来源：`chm / dsm_dem / manual / unknown` |
| `crown_volume_geo_est` | real | 否 | 冠积估计值 |
| `crown_volume_geo_real` | real | 否 | 冠积真实值 |
| `source_subimage_path` | text | 否 | 来源切片路径 |
| `created_at` | text | 是 | 创建时间，ISO 8601 |

约束：

- `PRIMARY KEY (observation_id)`
- `FOREIGN KEY (individual_id) REFERENCES tree_individuals(individual_id) ON DELETE SET NULL`
- `FOREIGN KEY (run_id) REFERENCES runs(run_id) ON DELETE CASCADE`
- `FOREIGN KEY (tract_phase_pk) REFERENCES tract_phases(tract_phase_pk) ON DELETE CASCADE`
- 可选复合外键：`FOREIGN KEY (tiff_id, phase_id) REFERENCES tiffs(tiff_id, phase_id) ON DELETE SET NULL`
- `CHECK (area_method IS NULL OR area_method IN ('bbox_product', 'polygon_area', 'mask_area'))`

## 4. ID 与生成规则

| ID | 格式 | 生成规则 |
|---|---|---|
| `region_id` | `市_县` | 从路径、元数据或用户输入中用低复杂度规则解析 |
| `tract_id` | 任意字符串 | 用户指定；未指定且唯一 TIFF 时取正射 TIFF 文件名 stem |
| `phase_id` | `YYYYMMDD` | 来自采集日期或用户输入 |
| `tiff_id` | 5 位哈希 | TIFF 四角坐标转 WGS84，经 3 位小数规范化后哈希 |
| `run_id` | 6 位哈希 | 运行任务生成 |
| `individual_id` | 8 位哈希 | 跨时相追踪生成，全局唯一 |

## 5. 配置项

建议新增面积估算配置：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `area_method` | `bbox_product` | 面积算法：检测框宽高相乘 |
| `volume_method` | 沿用当前配置 | 体积算法 |

`area_method` 的候选值：

- `bbox_product`: 当前默认，直接使用冠幅宽高估算面积。
- `polygon_area`: 使用树冠多边形面积。
- `mask_area`: 使用实例分割 mask 面积；当前为 TODO。

每次 run 应把最终生效配置写入 `runs.params_json`，每条观测也可把实际使用的面积算法写入 `tree_observations.area_method`，便于结果复现。

## 6. SQLite 到 PostGIS 演进

SQLite 阶段：

- JSON 字段以 TEXT 存储，应用层负责序列化和校验。
- 几何字段以 GeoJSON 或 WKT 文本存储。
- 跨表的复杂一致性，例如 `tiffs.phase_id` 必须等于 `tract_phases.phase_id`，由服务层和测试保证。

PostgreSQL/PostGIS 阶段：

- JSON 字段迁移为 JSONB。
- 几何字段迁移为 Geometry。
- `tiffs.phase_id` 与 `tract_phases.phase_id` 的一致性可用复合外键或触发器强化。

## 7. 验收测试

必须覆盖：

- 同一 `region_id` 下 `tract_id` 唯一，不同 `region_id` 可重名。
- 同一地块可拥有多个 `phase_id`，同一地块同一 `phase_id` 不可重复。
- `tiff_id + phase_id` 唯一标识 TIFF 图像。
- TIFF 路径版本默认读取最新日期 key，且不转换原始路径。
- `multisource_path_versions` 按文件类型独立维护路径版本。
- 单 TIFF 默认生成地块边界，多 TIFF 默认边界为空并等待人工指定。
- `footprint_bbox` 只表示 TIFF 覆盖外接矩形，检测框只存在于 `tree_observations`。
- `runs.task_type` 支持 `infer/train/report/batch/export/postprocess/import/track`。
- `runs.slice_size` 能复现切片推理。
- `tree_phase_states.lifecycle_status` 能表达 `new`。
- `tree_observations` 同时保存树冠像素宽高、地理宽高、面积估计值和真实值。
