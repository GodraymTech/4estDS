# 4estDS 技术方案快照

本文记录当前代码对应的技术方案，适合评审、交接和后续架构演进参考。

## 1. 项目目标

4estDS 面向红树林/林地正射影像，提供从影像输入到单木解译、统计报告、GIS 图层、跨时相生命周期追踪和前端一张图管理的完整链路。

当前支持:

- 超大 GeoTIFF/JPG/PNG 推理。
- SCOPE 自标定切片参数。
- COG/tiled TIFF 动态窗口读取。
- 静态切片落盘与缓存复用。
- `mock` 与 `ultralytics` 检测后端。
- WBF 去重融合。
- CHM、DSM/DEM、LAS 多源融合。
- SQLite 三层单木模型。
- PDF/Markdown/CSV 报告。
- GeoJSON/Shapefile/GPKG/CSV 导出。
- FastAPI + Dramatiq + Redis 异步作业。
- React/Vite/MapLibre 前端。

## 2. 总体架构

```text
Web/CLI/API
```

## 3. 关键子系统

### 3.1 预处理

入口: `preprocess.prepare_inference_image`

职责:

- 读取影像尺寸。
- 检查 TIFF 是否为 COG/tiled。
- 普通大 TIFF 在 dynamic 模式下自动转 COG。
- 决定 `direct`、`on_the_fly`、`physical_slice`。
- 触发 SCOPE 自标定。
- 静态模式下切片落盘并登记缓存。

### 3.2 推理内核

入口: `engine.run_inference`

职责:

- 生成窗口清单或读取物理瓦片清单。
- 通过 `ImageSource` 读窗。
- 通过 `BaseDetector.predict_batch` 推理。
- 检测框坐标回写到全图。
- 对内部切片边界截断框降权。
- WBF 融合去重。

### 3.3 服务层

入口: `service.run_inference_job`

职责:

- 创建 run_log。
- 调用推理业务流程。
- 失败时写 run_log 终态。
- 成功时可选发布为地块正式版本。

该层不依赖 Typer、FastAPI 或 Dramatiq，便于 CLI、Worker、未来 SDK 共用。

### 3.4 数据库

默认 SQLite，路径为 `~/.4estDS/db/4estds.sqlite`。

核心表:

- `run_logs`: 任务运行记录。
- `tracts`: 地块/时相。
- `tract_sources`: 多源文件。
- `tree_observations`: run 级单木观测。
- `tract_trees`: 地块正式规范单木。
- `tree_individuals`: 跨时相个体。

## 4. 前端业务模块

当前前端位于 `web/`:

- 框架: React 18 + Vite + TypeScript
- UI: Ant Design
- 地图: MapLibre

## 5. API 设计

所有业务路由挂在 `/api/v1`:

- `uploads`: 上传影像并返回存储 key。
- `jobs`: 输入检查、提交推理、查询状态、读取日志、浏览/下载产物。
- `tracts`: 地块、摘要、观测图层、报告、导出、变化对比。
- `tiles`: 本地 GeoTIFF XYZ PNG 瓦片。

健康探针不加版本前缀:

```text
GET /health
```

## 6. 当前创新点落地

### 创新点 A: SCOPE 自标定切片

已落地在 `preprocess/scope.py`、`preprocess/pipeline.py`、`preprocess/tiling.py`。

实际运行中用于大 TIFF 的 tile size/overlap 自动选择，并与 COG/静态切片路由结合。

### 创新点 B: 多源融合

已落地在 `fusion/` 和 `tasks/infer.py`。

支持:

- `--chm`
- `--dsm --dem`
- `--las --las-grid-size`

融合结果写入树高、冠幅面积、体积等字段，并登记 `tract_sources`。

### 创新点 C: 生命周期追踪

已落地在 `lifecycle/` 和 `4estds track`。

流程:

1. 按 `location` 找到多个时相地块。
2. 读取 active run 或最新成功 run。
3. 进行跨时相匹配。
4. 写入 `tree_individuals`。
5. 回填 `tract_trees.individual_id`。

## 7. 运行与部署最小组合

CLI 单机:

```bash
uv sync --extra detect --extra geo
uv run 4estds db init
uv run 4estds infer path/to/rgb.tif --arch ultralytics
```

Web 开发:

```bash
uv sync --all-extras
uv run uvicorn forestds.api.main:app --reload --host 127.0.0.1 --port 8000
redis-server
REDIS_URL=redis://localhost:6379/0 uv run dramatiq forestds.worker.actors --processes 1 --threads 1
cd web && mise exec -- pnpm run dev
```

## 8. 工程边界

后续改动应尽量保持:

- API 路由薄，业务不写进 router。
- CLI 只解析参数，不复制推理流程。
- Worker 只做队列与常驻模型缓存。
- 推理内核不直接依赖 FastAPI、Typer、Dramatiq。
- 数据库读写继续集中在 reader/writer。
- 前端请求继续集中在 `shared/api/endpoints.ts`。

## 9. 已知演进方向

- SQLite -> PostgreSQL/PostGIS。
- 本地瓦片端点 -> TiTiler/专业瓦片服务。
- 本地鉴权/角色模拟 -> 生产级租户、JWT、RLS。
- 单机 Worker -> 容器化 GPU 队列。
- 报告产物 -> 版本化对象存储。
