# 完整教程

本文按一次真实交付流程组织: 准备环境 -> 推理 -> 发布 -> 查看 -> 报告/导出 -> 多时相追踪 -> 前端任务中心。

## 1. 准备环境

```bash
uv sync --all-extras
uv run 4estds db init
```

运行期根目录默认是 `~/.4estDS`。如果希望把数据库、日志和输出写到项目外的固定目录:

```bash
export forestds_HOME=/data/forestds
uv run 4estds db init
```

注意: `forestds_HOME=/data/forestds` 会实际使用 `/data/forestds/.4estDS`。

配置优先级:

1. `configs/default.yaml`
2. `~/.4estDS/config/config.yaml`
3. 环境变量 `forestds_SECTION__KEY=value`
4. CLI 参数

常用环境变量:

```bash
export forestds_detect__device=cuda
export forestds_detect__verbose=false
export forestds_postprocess__draw_box=false
export REDIS_URL=redis://localhost:6379/0
```

## 2. 单图推理

### 2.1 冒烟验证

```bash
uv run 4estds infer data/多源数据研究_徐闻/DOM/xuwen_1024px.jpg --arch mock --no-draw-box --export-format geojson
```

`mock` 检测器用于验证工程链路，不代表真实识别效果。

### 2.2 真实模型

```bash
uv run 4estds infer path/to/rgb.tif \
  --arch ultralytics \
  --acquisition-time 20260706 \
  --location demo-plot \
  --export-format shp
```

当前真实检测后端由 `detect/backends/ultralytics.py` 适配，权重从配置读取:

```yaml
detect:
  arch: ultralytics
  models:
    ultralytics:
      weights: "path/to/best.pt"
```

也可以通过环境变量覆盖:

```bash
forestds_detect__device=cuda uv run 4estds infer path/to/rgb.tif --arch ultralytics
```

## 3. 预处理与切片路由

预处理入口:

```bash
uv run 4estds preprocess path/to/rgb.tif
uv run 4estds preprocess path/to/rgb.tif --action static --out-dir /tmp/forestds_tiles
```

当前路由逻辑:

- 小图: `direct`，直接整图推理。
- 大图 + tiled TIFF/COG + `dynamic`: `on_the_fly`，动态窗口读，不落盘切片。
- 大图 + 非 TIFF 或不支持随机读: `physical_slice`，静态切片落盘后推理。
- 普通非分块 TIFF 在 dynamic 模式下会尝试自动转换为同目录 `_cog.tif`。

如果用户显式传入 `--tile-size`，SCOPE 自标定会被短路，直接使用用户参数。

## 4. 批量推理

`infer` 本身支持多个路径或目录:

```bash
uv run 4estds infer path/to/images_dir --arch ultralytics
uv run 4estds infer a.tif b.tif c.tif --arch mock
```

也可以使用独立批处理命令:

```bash
uv run 4estds batch --input-dir path/to/images_dir --glob "*.tif" --arch ultralytics
```

批量流程会为每张影像创建独立 run，单图失败不阻断整批。

## 5. 多源融合

### 5.1 CHM

```bash
uv run 4estds infer rgb.tif --chm chm.tif --arch ultralytics
```

### 5.2 DSM/DEM

```bash
uv run 4estds infer rgb.tif --dsm dsm.tif --dem dem.tif --arch ultralytics
```

### 5.3 LAS/LAZ 点云

```bash
uv run 4estds infer rgb.tif --las cloud.las --las-grid-size 0.05 --arch ultralytics
```

多源数据会写入 `tract_sources`，树高、冠幅面积、体积等特征写入 `tree_observations`。DSM/LAS 可触发 `outputs/.../multisource/` 下的辅助可视化产物。

## 6. 报告与 GIS 导出

推理结束后会按配置尝试自动生成报告和 GIS 导出。也可以手动执行:

```bash
uv run 4estds report --tract-id <tract_id> --run-id <run_id> --format pdf
uv run 4estds report --acquisition-time 20260706 --location demo-plot --format md

uv run 4estds export --tract-id <tract_id> --run-id <run_id> --format geojson
uv run 4estds export --tract-id <tract_id> --format shp
```

支持格式:

- 报告: `md`、`csv`、`pdf`
- GIS 图层: `geojson`、`shp`、`gpkg`、`csv`

缺少图表/PDF依赖时，报告生成会尽量降级而不是阻断主流程。

## 7. 发布正式版本

CLI 推理默认 `publish=False`，不会自动把某次 run 发布为地块正式版本。发布命令:

```bash
uv run 4estds db promote --run-id <run_id>
```

发布会执行:

1. 确认 run 存在且状态为 `succeeded`。
2. 找到关联地块。
3. 将该 run 的观测整理为 `tract_trees`。
4. 回填 `tracts.active_run_id`。

前端/API 异步推理默认 `publish=True`，成功后会自动尝试发布。

## 8. 跨时相生命周期追踪

前提: 同一 `location` 下有多个不同 `acquisition_time` 的地块，并且每个地块都有可用 active run 或最近成功 run。

```bash
uv run 4estds track --location demo-plot
uv run 4estds track --location demo-plot --max-dist 20
```

默认使用匈牙利最优匹配；可用 `--greedy` 切到贪婪匹配。结果写入:

- `tree_individuals`: 跨时相个体
- `tract_trees.individual_id`: 规范单木回填个体 ID

### 9.2 Worker

```bash

```

### 9.3 前端

```bash
cd web
mise exec -- pnpm install --config.store-dir=/tmp/forestds-pnpm-store
mise exec -- pnpm run dev
```

打开 `http://127.0.0.1:5173`。

前端主要页面:

- `/map`: 一张图工作台
- `/dashboard`: 数据看板
- `/ledger`: 台账
- `/tasks`: 推理任务中心
- `/reports`: 报告中心
- `/alerts`: 预警中心
- `/invasion`: 入侵监测
- `/carbon`: 蓝碳/MRV
- `/admin`: 管理入口

## 10. 任务中心工作流

1. 在 `/tasks` 输入本机影像路径，或上传文件。
2. 调用 `/jobs/inspect-input` 检查路径、影像数量、CRS、尺寸和建议时相。
3. 配置模型架构、切片、重叠率、多源文件、导出格式等参数。
4. 提交 `/jobs/infer`。
5. 前端轮询 `/jobs/{job_id}` 和 `/jobs/{job_id}/logs`。
6. 作业完成后浏览报告、GIS 导出和运行产物。

## 11. 常见问题

### rtk 不可用

如果 shell 中没有 `rtk`，直接使用原生命令即可，不影响项目本身运行。

### 前端能打开但没有数据

确认 API 和数据库指向同一个 `forestds_HOME`/配置:

```bash
curl http://127.0.0.1:8000/api/v1/tracts
```

### `/tasks` 提交后一直 queued

通常是 Worker 或 Redis 没启动。检查:

```bash
redis-cli ping
REDIS_URL=redis://localhost:6379/0 uv run dramatiq forestds.worker.actors --processes 1 --threads 1
```

### 地图真影像瓦片不可见

内置瓦片端点只支持本地 GeoTIFF，并依赖 `rasterio/numpy/Pillow`。影像需要有 CRS，且最好是 tiled TIFF 或 COG。

### 大图推理很慢

优先使用 COG/tiled TIFF；普通 TIFF 在 dynamic 模式下会尝试自动转换为 `_cog.tif`。也可用 `--action static` 先落盘切片，用后续缓存复用。
